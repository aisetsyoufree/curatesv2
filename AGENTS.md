# Contributor Instructions

1. Read `MASTER.md` completely and read the assigned GitHub Issue.
2. Inspect Git status and recent commits; confirm the issue is Ready.
3. Work only within that issue on `task/<ID>-<short-name>`.
4. Do not publish or invent financial data; preserve fail-closed provenance rules.
5. Run the issue's verification and record results, commit/PR, impact, and risks in
   the issue before requesting review.
6. Do not self-merge or begin another issue. Codex owns integration and final QA.
7. Edit `MASTER.md` only when an approved product or architecture decision changes.

GitHub Issues/Project own task state. Do not create task ledgers, task packets, or
standalone review reports in the repository.
