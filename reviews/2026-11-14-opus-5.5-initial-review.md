# T002 — Independent Project-Control Review

**Model:** Claude Opus 5.5 (`claude-opus-5-5`), running in Claude Code  
**Date:** 2026-11-14  
**Mode:** Review only; no repository edits by reviewer  
**Reviewed commit:** `aed7166`

## 1. Executive verdict

**Approve the direction, but not as an executable spec yet.** The principles are
right: fail-closed publishing, immutable raw artifacts, deterministic extraction,
LLMs off the publish path, and tracking every institution rather than promising a
rate from each. So is the stack (Flask/Jinja, SQLite, Pi) and the one-writer rule.

Four gaps would cause rework or unsafe publishing if T004 or T010 started now:

1. There is no model of the conditions a rate applies under, so the "comparable by
   default" principle cannot be enforced.
2. There is no freshness or withdrawal policy, so fail-closed is undefined over time.
3. There is no rule for what can publish without a human, so the pipeline either
   blocks everything or turns review into rubber-stamping.
4. The task order is inverted in places. Taxonomy work is checked against fixtures
   that do not exist until M3, and registry research runs before there is an artifact
   store to hold its evidence.

All four can be settled in T003 as decisions. None needs code.

## 2. Blockers, most severe first

### B1. There is no model of rate conditions

Principle 5.9 requires like-for-like ranking, but no entity represents the conditions
a rate holds under. Real credit-union rate sheets publish:

- rates tiered by credit score, LTV/CLTV, loan amount or jumbo threshold, and lock period
- "as low as" rates
- relationship or autopay discounts
- ARM structure: initial period, index, margin, caps
- HELOC terms: index (usually Prime), margin, floor, ceiling, intro length, draw and
  repay periods, lien position
- occupancy and property type

Without an `OfferCondition`/`RateTier` entity and a set of canonical
`ComparisonScenario`s, T044 and T053 cannot meet their acceptance criteria, and T010
will be redone.

**Recommendation:** add both entities to Section 8. Make T003 record the default
scenario. Recommended default: owner-occupied single-family primary residence,
conforming amount, the lender's lowest published tier, with the scenario, points and
conditions always shown.

### B2. There is no freshness or withdrawal policy

"Previous good snapshot survives failure" (T050) plus "freshness warnings" (Section 7)
means a broken worker keeps serving stale rates indefinitely, with only a warning.
That contradicts fail-closed. Also undefined:

- how often collection runs
- how old an observation can be before it is depublished, per product family
- whether one failed source withdraws its offers or keeps the last good value
- an emergency unpublish for a single offer or institution

**Recommendation:** add freshness and withdrawal principles, and add a kill switch to
T050's acceptance criteria.

### B3. There is no rule for publishing without human review

Principle 5.6 and stage 9 imply human review, and Sid is the only human. Daily
collection across the full roster cannot be hand-reviewed on every change.

**Recommendation:** define auto-publish eligibility. An offer can publish without
review only if all of these hold:

- the source is approved
- the parser version is approved for that source
- the structural fingerprint is unchanged since the last approved extraction
- every value is within its validation bounds
- the change since the last published value is within a tolerance, for example
  no more than 50 basis points

Mandatory review applies to first publication, fingerprint changes, out-of-tolerance
changes and any OCR-derived value. This belongs in T010 and T045 but must be decided
in T003.

### B4. Dependencies are inverted

- T011's acceptance criteria say "cover fixtures", but fixtures come from T030 and
  T033 in M3.
- T022 and T023 ("evidence-backed" catalog and sources) run before T031 and T032
  exist. The evidence would end up in LLM chat logs or notes, not immutable artifacts.

That breaks principles 5.2 and 5.7, and research could carry hallucinated URLs into
the registry.

**Recommendation:**

- Move pilot selection and fixture capture ahead of T011, or seed fixtures from V1
  artifacts that have been re-fetched.
- Move T031 and a minimal T032 ahead of T022 and T023.
- Require that every registry claim cites a `RawArtifact` ID.

### B5. The product taxonomy contradicts itself

Section 4.3 says refinance is a purpose, not a product family, but Section 4.2 lists
rate-and-term and cash-out refinance as families. Also undecided: whether FHA, VA,
USDA, jumbo, ARMs, first-time-buyer and MassHousing-partner programs are in scope.

### B6. The ledger breaks its own definition of ready

T003 is marked `ready` while T002 is `in_progress`, although Section 14 requires
dependencies to be done.

## 3. Important improvements

### Data semantics

- Store rates as `Decimal` or integer thousandths of a percent, never floats. Record
  the original text alongside the parsed value.
- Store timestamps in UTC and display them in America/New_York.
- Validation should warn, not reject, when APR is below note rate. That case can be
  legitimate with lender credits and some ARMs.
- HELOC APR under open-end rules does not have the same relationship to fees as a
  closed-end mortgage, so mortgage APR checks cannot be reused blindly.
- Decide whether a note rate can publish without an APR. Recommended: browse-only,
  never ranked.

### Provenance

- Define a locator format per artifact type:
  - HTML: XPath or CSS selector plus a text-span hash
  - PDF: page number plus bounding box
  - JSON/XHR: RFC 6901 JSON Pointer
- Text offsets must name which normalization they are relative to.
- Record git SHA, parser ID/version, and configuration hash on every extraction run.
- Derived fields cite the rule ID that produced them.
- Public evidence should be source URL, observation time and a text excerpt. Keep raw
  artifacts and screenshots private to reduce terms-of-use and trademark risk.

### Institutions

- Name the roster source: NCUA quarterly call-report data, cross-checked against the
  Massachusetts Division of Banks list.
- Define lifecycle states such as `active`, `merged_into`, `liquidated`, and
  `converted`.
- Define scope as all active MA-headquartered credit unions, with "no home lending"
  as a legitimate catalog status.

### Collection ethics

- Honor `robots.txt`, identify with a contact User-Agent, never bypass CAPTCHAs, bot
  protection or logins, and set per-host rate limits.
- "Hostile" pilot cases must mean "record as blocked", not "defeat".
- Add a collection-policy task before the fetch worker.

### Architecture

- The web process should read only a separate read-only `published.sqlite`, produced
  by T050 and swapped with an atomic rename.
- Keep the artifact store on the filesystem, content-addressed by SHA-256, not as
  SQLite BLOBs. Add a retention policy.
- Back up off-device using the SQLite online backup API or Litestream.

### Pi and hosting

- Use NVMe or SSD, not an SD card, for WAL and artifacts.
- Pin Python with `uv`-managed interpreters.
- Run an early spike to confirm Playwright Chromium on arm64 for the selected OS.
- Decide between direct home exposure and a tunnel/CDN; it affects security, uptime,
  Core Web Vitals and ISP terms.

### Development environment

The repository lives in iCloud Drive. iCloud sync can conflict with `.git`, SQLite
WAL/SHM files and `.venv`. Move the repository out of iCloud, or at minimum keep
`data/`, `*.sqlite*` and `.venv` outside the synced path. Resolve this before T004.

### Frontend toolchain

- Use the Tailwind standalone CLI so the project needs no Node toolchain.
- Vendor HTMX locally.

### Analytics, SEO and ads

- Pick `gtag.js` or GTM rather than supporting both. `gtag.js` is sufficient here.
- Make consent defaults region-specific and record the intended regimes.
- Serve `ads.txt` only after a publisher ID is configured.
- Mark thin institution pages `noindex` until they contain meaningful original
  content, and exclude them from the sitemap.
- Write a CSP compatible with the selected Google tags.
- Avoid "best rate" language. Sort by APR only within a comparable scenario and keep
  points visible.

### Workflow

- Having every task edit `PROJECT.md` will create conflicts across worktrees. Workers
  should write `tasks/T0xx.md` handoffs; only the integrator updates the ledger and
  change log.
- Review reports should be committed verbatim by the integrator.
- `AGENTS.md` should explicitly exempt review-only models from editing the ledger.

### Test ownership

T013 is the most safety-critical test suite and should not be owned solely by the
mechanical-work model. Sol should specify the invariants, Sonnet or Grok should
implement them, and Gemini may expand cases.

### Ordering

- Add an early vertical slice: one CU and one static HTML product flowing through
  artifact, extraction, validation, snapshot and page.
- T004 does not depend on most review outcomes, except the iCloud and `uv` decisions.

### Missing tasks

- V1 asset inventory, with V1 data treated only as unverified leads
- Collection and legal policy
- Pi platform spike
- Security hardening
- Dataset license and export schema versioning
- Launch gate with milestone exit criteria
- Corrections workflow

## 4. Explicit agreements

- Track every institution rather than promise a rate from each.
- Treat explicit absence as a valid result.
- No LLM at runtime, and LLMs never approve financial values.
- Raw before normalized, append-only history, and content hashing.
- `points = null` versus zero, rate distinct from APR, three timestamps, and HELOC
  introductory rates distinct from post-intro rates.
- Flask/Jinja, SQLite WAL, a single writer, separate web/worker processes, and
  systemd are appropriate for a Pi.
- Playwright only where needed; OCR requires human review before first publication.
- Typed product-specific structures are preferable to one flat table.
- Coverage should be reported by pipeline stage.
- Ads should not appear on quarantine or thin pages.
- One writer per task, independent review, cross-vendor adversarial audit, and Sid as
  final approver.

## 5. Explicit disagreements

1. Refinance types are listed as product families despite being defined as purposes.
2. T050 preserves the previous snapshot without an age limit.
3. T011 precedes fixtures, and T022/T023 precede the artifact store.
4. T013 is assigned to the mechanical-work model.
5. Every task editing `PROJECT.md` will produce avoidable conflicts.
6. The plan leaves `gtag.js` versus GTM undecided.
7. Horizontal milestones lack an early end-to-end vertical slice.
