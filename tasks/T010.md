# T010 — Canonical domain data contract

## Objective

Specify the versioned domain contracts that every collector, parser, validator,
publisher, and page must use before the database schema is designed.

## Dependencies

T003 is done. The initial contract must be reviewed before T008, T011, T012, T013,
or T031 begins.

## Non-goals

No ORM schema, scraper implementation, UI, or invented source data.

## Allowed changes

Contract specifications, examples, schema fixtures, architecture decision records,
and this task packet. The integrator owns `PROJECT.md`.

## Acceptance criteria

- Specify identifiers, lifecycle/status enums, null semantics, Decimal encoding,
  UTC timestamps, versioning, and relationships for every entity in Section 8.
- Keep product-family types distinct while defining a shared base offer.
- Encode `points = null` versus zero, conditions/tiers, canonical scenario identity,
  source provenance, evidence locators, parser/version fingerprints, validation,
  review, withdrawal, and snapshot membership.
- Define positive and negative examples plus backward-compatibility rules.
- Make publication eligibility deterministically computable without an LLM.

## Required verification

- Validate all machine-readable schemas and examples with the chosen schema tool.
- Round-trip Decimal and timestamp examples without loss.
- Demonstrate that incomplete, stale, mismatched-scenario, and unreviewed offers
  cannot satisfy the publication contract.
- Obtain an independent architecture review and record its findings.
