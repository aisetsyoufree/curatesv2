# T010 — Canonical domain data contract

## Objective

Specify the versioned domain contracts that every collector, parser, validator,
publisher, and page must use before the database schema is designed.

## Dependencies

T004 is done. The initial contract must be reviewed before T008, T011, T012, T013,
or T031 begins.

## Non-goals

No ORM schema, scraper implementation, UI, or invented source data.

## Allowed changes

Contract specifications, examples, schema fixtures, architecture decision records,
and this task packet. The integrator owns `PROJECT.md`.

## Acceptance criteria

- Specify identifiers, lifecycle/status enums, null semantics, Decimal encoding,
  UTC timestamps, versioning, and relationships for every entity in Section 8.
- Keep product-family types distinct while defining a shared base offer.
- Separate conforming status, government guaranty, borrower programs, and partner
  programs; encode membership eligibility without inventing unsupported categories.
- Encode `points = null` versus zero, conditions/tiers, canonical scenario identity,
  tri-state scenario matching, source provenance, rendered/image evidence locators,
  parser/version fingerprints, validation, review, correction, withdrawal,
  `valid_until`, emergency denial, and snapshot membership.
- Represent shared vendor/CUSO sources explicitly through service providers and
  institution-source relationships; shared URLs are never treated as identity proof.
- Define structural fingerprints so mutable financial magnitudes are compared but do
  not themselves make every otherwise unchanged source structurally new.
- Define HELOC post-intro derivation provenance. A computed APR is rankable only from
  an approved index observation plus source-stated index, margin, and floor rules;
  otherwise it remains incomplete and browse-only.
- Define positive and negative examples plus backward-compatibility rules.
- Make publication eligibility deterministically computable without an LLM.

## Data, migration, and publication impact

No live data or migration. The versioned contract constrains all later schemas,
fixtures, validation, publication, and public representations.

## Required verification

- `uv run pytest tests/contracts`
- Validate all machine-readable schemas and examples with the committed schema tool.
- Round-trip Decimal and timestamp examples without loss.
- Demonstrate that incomplete, stale, mismatched-scenario, and unreviewed offers
  cannot satisfy the publication contract.
- Obtain an independent architecture review and record its findings.
